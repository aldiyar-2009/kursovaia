# StudyPlan: переработка структуры, дизайна, языков, импорта LMS и базы данных

Дата: 2026-10-26. Статус: черновик на согласование.

## Зачем

StudyPlan — курсовая работа: офлайн-органайзер студента Astana IT University. Сейчас приложение выглядит переполненным (17 пунктов меню), показывает фейковые данные каждому новому пользователю, считает оценки неправильно, существует только в тёмной «ИИ-шной» теме и только на русском. Вход в LMS сделан через форму логина/пароля, которая для студентов не работает (студенты входят через Microsoft 365), и при этом пароль уходит на наш сервер.

Цель — чтобы приложение выглядело и ощущалось как продукт крупной компании: спокойное, понятное, без лишнего, с реальными данными студента из LMS.

Пользователь будет показывать приложение на защите на Android-телефоне; запасной вариант — Windows.

## Цели

1. Оставить только то, чем студенты реально пользуются; 4 вкладки + «Ещё».
2. Новый пользователь видит пустое приложение, где каждый экран объясняет, для чего он и что сделать первым.
3. Правильный расчёт оценок, правила вынесены в одно место, чтобы их можно было поправить, когда пользователь уточнит правила АИТУ.
4. Новая визуальная система, светлая и тёмная тема, выбор пользователя.
5. Три языка: русский, английский, казахский; выбор пользователя.
6. Импорт оценок, дедлайнов и профиля из LMS через вход Microsoft по кнопке; данные сохраняются в аккаунт StudyPlan и синхронизируются на все устройства.
7. База данных сервера — PostgreSQL на Supabase.

## Не цели

- Замена Node-бэкенда на Supabase Auth / Supabase client SDK. Бэкенд остаётся, Supabase — только хранилище PostgreSQL.
- Импорт данных Microsoft 365 вне LMS (Outlook, Teams, OneDrive).
- Вход в LMS в веб-версии (браузер не даёт технической возможности). Веб показывает уже импортированные данные.
- Новая функциональность карты кампуса (у пользователя есть идея, обсудим отдельно). Страница карты остаётся как есть, только в новом дизайне.
- Хостинг бэкенда в облаке.

## Анти-цели (провал, даже если «работает»)

- Дизайн, который выглядит сгенерированным ИИ: эмодзи, градиенты, свечение, большие скругления повсюду, тени, неоновые акценты, «стеклянные» карточки, иконка у каждой строки.
- Любые фейковые цифры у реального пользователя (оценки, GPA, суммы стипендии, бейджи).
- Пароль Microsoft или cookie сессии LMS попадают на сервер StudyPlan.
- Машинный или неправильный казахский перевод.

## Ограничения

- Офлайн-архитектура сохраняется: drift локально, `POST /api/sync` с LWW, контракт таблиц в `backend/src/db/schema.js` ↔ `mobile/lib/core/database/app_database.dart` (см. CLAUDE.md).
- Платформы: Android, iOS, Windows, Web. Веб должен компилироваться (условные импорты для webview).
- CI запускает `flutter analyze` и `flutter test` — должны проходить.
- Бэкенд-тесты (`npm test`) должны проходить; тесты используют SQLite в памяти и сид — сид-файл остаётся для тестов и ручного `npm run seed`.

## Этап 1. Структура и чистка

### Навигация (решено с пользователем)

Телефон: нижняя панель из 5 пунктов — Главная, Расписание, Задания, Оценки, Ещё. Широкий экран (≥ 840 px, Windows): та же структура в виде боковой панели слева. Выдвижное меню (drawer) убирается.

| Вкладка | Содержимое | Что влито |
|---|---|---|
| Главная | Сегодня: следующая пара, ближайшие дедлайны (свои + LMS), последние оценки | Портал, Таймлайн дня |
| Расписание | Пары по дням недели (чёт/нечёт), переключатель на академический календарь | Календарь 2026–2027 |
| Задания | Свои задания и дедлайны из LMS, фильтр «Все / Мои / LMS / Выполненные» | Домашние задания |
| Оценки | Список предметов с итогом; внутри предмета — компоненты; блоки «Что будет, если…», «Риск отработки», «Стипендия»; кнопка «Обновить из LMS» | Симулятор, Отработки, Повышка, LMS-интеграция |
| Ещё | Группа (участники, приглашение, материалы группы), Карта AITU, Профиль и настройки (тема, язык, импорт LMS, напоминания, сервер, выход) | Напоминания & .ICS, Файлы, Администрирование |

### Группа (решение принято мной по просьбе пользователя «как удобнее»)

Студенты АИТУ уже общаются в WhatsApp/Telegram — встроенным чатом пользоваться не будут. Поэтому **чат убирается целиком**, а группа становится общим местом для того, что в мессенджере теряется: групповые дедлайны и материалы.

- **Роли староста/студент убираются.** Все участники группы равны: любой может опубликовать групповое задание и загрузить материал; удалить — только автор. Серверная проверка «только headman публикует `is_group`» меняется на «только участник этой группы». Столбец `users.role` остаётся в БД, но не используется в логике и интерфейсе. Экран «Администрирование» удаляется.
- **Вступление:** кнопка «Пригласить» открывает системное меню «Поделиться» (`share_plus`) с готовым текстом для WhatsApp: «Вступай в группу <название> в StudyPlan: код ABC123» + ссылка на веб-версию `<сервер>/join/ABC123`. Получатель либо вводит код в приложении (Группа → «Вступить по коду»), либо открывает ссылку: веб-версия после входа/регистрации подставляет код в поле вступления. Нативные deep links на Android/iOS не делаются (требуют подтверждённого домена).
- **Создание группы:** Группа → «Создать группу» (название) → сразу экран приглашения.
- **Экран группы:** название, код с кнопками «Копировать» и «Пригласить», список участников (имя), «Материалы группы», «Покинуть группу».
- **Материалы группы:** экран «Файлы» переделывается под серверный API `/api/materials` (он уже написан: загрузка, список, удаление). Фильтр по предмету. Без группы — пустое состояние «Вступите в группу или создайте её, чтобы делиться материалами». Личный локальный список файлов убирается (личные файлы прикрепляются к заданиям, как и сейчас). Список материалов кэшируется для просмотра офлайн; загрузка и скачивание требуют сети.
- **Групповые задания** показываются во вкладке «Задания» вместе со своими и LMS (фильтр «Группа»), с именем автора.
- **Удаляется:** экран чата, `ChatMessages`/`ChatDao` в приложении, обработка чата в `/api/sync`, маршруты `/api/chat/*`, Socket.IO-сервер и `realtime/` (без чата он не нужен; синхронизация групповых заданий работает через обычный `/api/sync`), неиспользуемые пакеты `socket_io_client`, `url_launcher` (если не понадобится). Таблица `chat_messages` в БД не удаляется миграцией (без разрушительных изменений), просто не используется. Связанные бэкенд-тесты обновляются.
- **Нужно на сервере:** `GET /api/groups/me/members` (имя, id) — нового эндпоинта не хватает; разрешить загрузку/удаление материалов любому участнику (проверить текущие правила в `materials.service.js`).

Переходы внутри «Ещё» и в деталях предмета/задания — обычные `Navigator.push` с системной кнопкой «назад». Системная кнопка «назад» на Android с не-главной вкладки возвращает на Главную, с Главной — выходит.

### Убрать демо-данные (полный список — отчёт агента в истории; ключевое)

- `AituDataService`: убрать демо-предметы, демо-отработку, фейковый список групп, `_isLmsConnected = true` по умолчанию, подмену нулевой оценки на 85. Сервис заменяется данными из drift (этап 4); до этапа 4 — пустой.
- Экран входа: убрать кнопки быстрого входа демо-аккаунтами и предзаполненный код группы `AITU26`, подсказку про `IVT21A`.
- Главная/портал: убрать захардкоженные GPA, «Химия 45.7», суммы ₸, три «сегодняшние» пары — читать из drift.
- Бейджи в меню (82.6 / 1 / NEW / 90+) — убрать.
- Отработки: убрать формулу с `45.7`. Стипендия: убрать суммы 43 574 / 50 110 ₸.
- Файлы: убрать 7 сид-файлов и фейковую загрузку (экран переделывается в «Материалы группы», см. выше).
- Напоминания: убрать 2 фейковых напоминания и `mockLessons`; экспорт .ICS берёт пары из drift.
- Профиль/шелл: убрать запасные значения групп `BDA-2601` / `ИВТ-21` / `IVT21A` / «семестр 3» — показывать «Группа не выбрана».
- Выбор группы из фейкового списка в шапке — убрать (группа пользователя берётся из `/groups/me`, вступление — по коду).
- Бэкенд: `server.js` больше не запускает сид автоматически при пустой таблице `users`. Сид остаётся для тестов и ручного `npm run seed`.
- Академический календарь 2026/27 (12 событий) — это справочные данные, не пользовательские; остаются.
- Точки на карте кампуса — справочные; остаются.

### Пустые состояния

Каждый экран без данных показывает: короткий заголовок (что здесь будет), одну строку пояснения и одну основную кнопку. Без иллюстраций и эмодзи. Примеры:

- Расписание: «Расписание пусто» / «Добавьте пары, чтобы видеть следующую пару на главной» / [Добавить пару].
- Оценки: «Оценок пока нет» / «Импортируйте их из LMS — вход через ваш аккаунт Microsoft АИТУ» / [Импортировать из LMS] (на вебе — «Импорт доступен в приложении для Android, iOS и Windows»).
- Задания: «Заданий нет» / «Создайте задание или импортируйте дедлайны из LMS» / [Новое задание].
- Главная без всего: короткий чек-лист первых шагов (добавить расписание, импортировать из LMS, вступить в группу), пункты исчезают по мере выполнения.

### Правила оценивания

Официальная политика АИТУ в открытом доступе не найдена. Пользователь уточнит у друга. До этого — общепринятая в казахстанских вузах схема. Все числа — в одном файле `mobile/lib/features/grades/domain/grading_rules.dart`, чтобы поправить в одном месте.

- Рейтинг допуска = среднее Register Midterm и Register Endterm (0–100).
- Итог по предмету = 0.6 × рейтинг допуска + 0.4 × финальный экзамен.
- Допуск к экзамену: рейтинг допуска ≥ 50. Экзамен засчитан: ≥ 50. Предмет сдан: итог ≥ 50, допуск и экзамен засчитаны. Иначе — риск отработки / отработка.
- Если LMS отдаёт только итог (без компонентов) — используем итог как есть.
- Оценки можно вводить вручную (на вебе, при сбое импорта, для предметов вне LMS): «Добавить предмет» и редактирование компонентов в деталях предмета. У записи есть источник `lms` / `manual`; повторный импорт не трогает `manual`-записи, а для `lms`-записей перезаписывает компоненты значениями из LMS (кредиты — нет).
- Курсы: импортируются все, что отдаёт LMS (текущие и прошлые, поле `classification`: `inprogress` / `past` / `future`). На экране по умолчанию — текущие; прошлые — свёрнутым разделом. GPA показывается за текущий семестр и общий.
- При импорте для каждого курса, если в расписании нет предмета с тем же названием, создаётся предмет (`subjects`), чтобы при добавлении пар не было дублей. Курс хранит ссылку `subject_id` (nullable).
- Шкала: A 95–100 (4.00), A- 90–94 (3.67), B+ 85–89 (3.33), B 80–84 (3.00), B- 75–79 (2.67), C+ 70–74 (2.33), C 65–69 (2.00), C- 60–64 (1.67), D+ 55–59 (1.33), D 50–54 (1.00), F 0–49 (0). Единый порог «сдано» — 50 (сейчас местами 51 — ошибка).
- Средний балл и GPA — взвешенные по кредитам. Кредиты предмета: значение по умолчанию 5, пользователь может изменить в деталях предмета.
- Предметы без оценок (ещё не выставлены, LMS вернул «-» или пусто) в средний не входят и показываются «нет оценки», а не 0 и не 85.
- Повышенная стипендия: все предметы с оценкой ≥ 90. Обычная: все ≥ 75. Суммы стипендии не показываются.
- «Что будет, если…»: пользователь вводит гипотетический балл за ещё не выставленный компонент (например, финал) → показываем итог предмета, букву, новый GPA, статус стипендии. Гипотетические значения не сохраняются.
- «Риск отработки»: предметы, где допуск < 50, или где для итога ≥ 50 нужен финал > 100 (недостижимо), или итог < 50. Для предметов с ещё не сданным финалом показываем «нужно минимум N на финале, чтобы сдать / чтобы было 90+».
- Номер учебной недели (чёт/нечёт) считается от `groups.semester_start`, если он есть; иначе от 1 сентября текущего учебного года (сейчас для января–августа получаются отрицательные недели — ошибка).

## Этап 2. Дизайн

### Принципы

Как в продуктах уровня Linear / Notion / Apple Settings: типографика и отступы вместо декора.

- Нейтральная палитра (оттенки серого) + один акцент. Основная кнопка — почти чёрная в светлой теме, почти белая в тёмной (как в референсе aitu-college.vercel.app).
- Цвет несёт смысл только в оценках/статусах: зелёный (сдано, 90+), жёлтый (риск), красный (отработка). Приглушённые, не неоновые.
- Без теней. Разделение — 1 px границы и фон поверхностей.
- Скругления: 8 px для кнопок, полей, карточек; 12 px — только для нижних листов и диалогов. Не «пилюли» повсюду.
- Без эмодзи, без градиентов, без свечения, без анимаций ради анимаций (только стандартные переходы).
- Списки — строки с разделителями, а не стопка карточек. Иконки — только там, где они помогают навигации (нижняя панель, действия), один стиль — Material Symbols Outlined (идёт с Flutter).
- Шрифт Inter, вшитый в приложение (`assets/fonts`, лицензия OFL), чтобы работал офлайн. Размеры: 28/22/17/15/13/12; цифры оценок — tabular figures.
- Отступы по сетке 4 px; поля экрана 16 px.
- Плотность как у нативных приложений: строка списка 56–64 px, кнопка 44–48 px.

### Темы

- `ThemeData` для светлой и тёмной темы + `ThemeExtension` с семантическими цветами (поверхности, границы, текст основной/вторичный, статусы оценок).
- Все виджеты берут цвета из темы (`Theme.of(context)` / расширение), прямые обращения к `AppColors.*` и `Colors.*` убираются.
- Настройка «Тема: Системная / Светлая / Тёмная», хранится в SharedPreferences, по умолчанию «Системная».

### Объём

Перерисовываются все оставшиеся экраны, диалоги и листы: вход/регистрация, сплэш, шелл и навигация, Главная, Расписание (+ академический календарь), Задания (+ лист деталей задания), Оценки (+ детали предмета, ручной ввод, «что если», отработки, стипендия), Группа (+ приглашение, материалы), Карта, Профиль/настройки, диалог сервера, окно импорта LMS.

## Порядок и параллельная работа

Срок не давит. Этапы идут по порядку 1 → 5, но независимые части выполняются параллельно агентами в отдельных git worktree: бэкенд (Supabase, новые таблицы, группа, удаление чата) — параллельно с мобильной частью; парсеры LMS — параллельно с дизайном; перерисовка экранов — по разделам после появления общей темы и навигации. ## Этап 3. Три языка

- `flutter_localizations` + `gen-l10n`, файлы `lib/l10n/app_ru.arb`, `app_en.arb`, `app_kk.arb`. Шаблон — русский.
- Все ~700 строк интерфейса выносятся в ARB. Русские строки, используемые как логические ключи (статусы отработок, вкладки админки, категории календаря), заменяются на enum'ы.
- Настройка «Язык: Системный / Русский / English / Қазақша», хранится в SharedPreferences. Системный: если язык устройства kk/en/ru — он, иначе русский.
- Даты и числа форматируются через `intl` с локалью (`kk` поддерживается intl).
- Казахский: перевод выполняется вручную с проверкой терминов по открытым источникам (официальные сайты казахстанских вузов на казахском, глоссарии). Отдельным файлом `docs/i18n-kk-review.md` — список строк, в которых есть сомнения, для проверки носителем (у пользователя есть друг в АИТУ). Академические термины — так, как их используют казахстанские вузы (например «бағалар», «сабақ кестесі», «тапсырмалар»).
- Импортированные из LMS названия курсов не переводятся (их язык задаёт LMS).

## Этап 4. Импорт из LMS через Microsoft

### Поток

1. Оценки → «Импортировать из LMS» (или Профиль → LMS).
2. Открывается экран со встроенным браузером (`flutter_inappwebview`; Android, iOS, Windows — на Windows нужен WebView2 Runtime, он есть в Windows 11). Загружается `https://lms.astanait.edu.kz/auth/oidc/?source=loginpage`.
3. Пользователь входит на странице Microsoft. Приложение не трогает поля ввода.
4. Когда браузер оказывается на `lms.astanait.edu.kz` вне страниц логина и в странице есть `M.cfg.sesskey`, приложение считает вход выполненным и показывает «Загружаем данные…».
5. Данные забираются JavaScript-запросами из контекста страницы (same-origin, cookie прикладываются браузером, cookie в Dart не извлекаются):
   - Основной путь — внутренний AJAX Moodle `POST /lib/ajax/service.php?sesskey=…` с функциями, которые использует сам веб-интерфейс Moodle: `core_course_get_enrolled_courses_by_timeline_classification` (курсы), `core_calendar_get_action_events_by_timesort` (дедлайны), `gradereport_overview_get_course_grades` и/или `gradereport_user_get_grade_items` (оценки и компоненты), профиль — из `M.cfg`/страницы профиля.
   - Если функция недоступна через AJAX (ошибка доступа) — запасной путь: загрузить HTML нужной страницы через `fetch` и разобрать (`/grade/report/overview/index.php`, `/course/user.php?mode=grade&id=…`, `/calendar/view.php?view=upcoming`, `/user/profile.php`). Разбор — в Dart, чистыми функциями, покрытыми тестами на реальных HTML-образцах (из HAR пользователя, обезличенных).
6. После загрузки — выход из LMS не выполняется (чтобы Microsoft в следующий раз пропустил без пароля), но окно браузера закрывается; в приложении сессия LMS нигде не сохраняется.
7. Данные записываются в drift (см. ниже) и уходят на сервер обычной синхронизацией.
8. В Оценках показывается «Последний импорт: дата, время». На вебе кнопка импорта заменена пояснением.

Повторный импорт: курсы/оценки/события, пришедшие из LMS, обновляются по LMS-идентификатору (upsert); исчезнувшие из LMS — помечаются удалёнными. Собственные задания пользователя не трогаются. Отметка «выполнено» на LMS-дедлайне сохраняется между импортами.

### Что импортируется (по просьбе пользователя — «оценки, расписание, файлы и так далее»)

- **Оценки** — курсы и компоненты (см. правила оценивания).
- **Дедлайны** — задания, тесты (`core_calendar_get_action_events_by_timesort`).
- **Расписание пар** — из занятий модуля «Attendance»: каждое занятие (в HAR видно как события `mod_attendance` «Attendance (Group BDA-2608)») — это реальная пара с датой, временем начала и длительностью. Берутся через календарный AJAX (`core_calendar_get_calendar_upcoming_view` / `core_calendar_get_calendar_monthly_view` за нужные месяцы семестра; при недоступности — HTML `calendar/view.php?view=day|upcoming`). Сохраняются в `lms_events` с `event_type = 'class'`. Экран «Расписание» показывает вместе ручные пары (`lessons`) и импортированные занятия (по конкретным датам), с пометкой «LMS». Если у одной пары есть и ручная запись, и LMS — показываются обе (пользователь может удалить ручную). Аудитория — если есть в описании события.
- **Материалы курсов** — список файлов, папок, ссылок и страниц курсов (AJAX `core_course_get_contents`, при недоступности — разбор HTML `/course/view.php?id=…`). Сохраняется только список: название, тип, курс, ссылка. Нажатие открывает материал в системном браузере (там вход через Microsoft выполняется автоматически, если пользователь уже входил). Файлы при импорте не скачиваются (объём). Экран «Материалы» получает два раздела: «Группа» и «LMS».
- **Профиль** — ФИО, почта, группа из LMS.
- **Не импортируется**: данные Microsoft 365 вне LMS (Outlook, Teams, OneDrive). Для доступа к ним нужна регистрация приложения в Microsoft Entra и согласие администратора университета — недоступно студенту.

Каждый вид данных импортируется независимо: если, например, материалы не загрузились, оценки и расписание всё равно сохраняются, а пользователь видит, что именно не удалось.

### Новые синхронизируемые таблицы

`lms_courses`: id (UUID клиента), source (`lms`/`manual`), lms_course_id (nullable для manual), subject_id (nullable), classification, title, teacher_name, credits (по умолчанию 5, редактируется пользователем, повторный импорт не перезаписывает), register_midterm, register_endterm, final_exam, total (всё nullable real), grade_items_json (компоненты как есть, для экрана деталей), imported_at, is_deleted, updated_at.

`lms_events`: id, lms_event_id, lms_course_id (nullable), title, course_title, event_type (`deadline` / `class` / `other`), module_name (assign, quiz, attendance…), starts_at (epoch ms; для дедлайна — срок), duration_min (nullable), location (nullable), url, is_done, imported_at, is_deleted, updated_at.

`lms_materials`: id, lms_module_id, lms_course_id, course_title, section_title, title, material_type (`file` / `folder` / `url` / `page` / `other`), url, imported_at, is_deleted, updated_at.

Добавление по чек-листу из CLAUDE.md: Knex-миграция, `SYNC_TABLES` + `SYNC_ORDER` в `schema.js`, drift-таблицы + регенерация `.g.dart` + миграция схемы drift (schemaVersion 1 → 2), маппинг push/pull в `sync_repository.dart`, бэкенд-тесты синхронизации для новых таблиц.

Профиль LMS (ФИО, почта, ID в LMS) сохраняется в SharedPreferences устройства и показывается в профиле; на сервер не уходит (не нужен для работы).

## Этап 5. Supabase

- Проект Supabase `studyplan` уже создан (ref `ncqwycbtfxboqyhmzbjr`, регион eu-central-1).
- Бэкенд подключается через `DB_CLIENT=pg` + `DATABASE_URL` (строка подключения Supabase, Session pooler, порт 5432 — Knex использует транзакции, transaction pooler не подходит).
- `env.js`: если задан `DATABASE_URL`, SSL включается автоматически, а не только при `PG_SSL`. Проверка сертификата не отключается: корневой сертификат Supabase (скачивается в панели, Database Settings → SSL) кладётся в `backend/certs/supabase-ca.crt` и передаётся как `ssl: { ca }`; путь настраивается переменной `PG_SSL_CA`. Существующий режим `rejectUnauthorized: false` убирается.
- Миграции Knex применяются к Supabase (`npm run migrate`). Сид не запускается.
- Безопасность: все таблицы лежат в схеме `public`, которую Supabase открывает через свой REST API по публичному anon-ключу. На всех таблицах включается Row Level Security без политик (миграцией, только для pg) — REST API их не отдаёт, а бэкенд подключается ролью `postgres` и RLS не затрагивается.
- Пароль базы пользователь задаёт сам в панели Supabase и вписывает в `backend/.env`; в репозиторий не попадает. `.env.example` обновляется с примером строки.
- Локальная разработка и тесты продолжают работать на SQLite.

## Решения, принятые мной (не согласованы явно)

- 5 пунктов в нижней панели (4 вкладки + «Ещё»); боковая панель на широком экране с порога 840 px.
- Правила оценивания — общеказахстанская схема 60/40 до уточнения от пользователя.
- Кредиты по умолчанию 5 и редактируемые.
- Порог обычной стипендии 75 (вместо 70).
- Шрифт Inter, вшитый; иконки Material Outlined.
- AJAX Moodle как основной путь импорта, HTML — запасной.
- Профиль LMS не синхронизируется на сервер.
- Включение RLS на Supabase.
- Чат и Socket.IO убираются; роли убираются; группа = участники + приглашение через WhatsApp + групповые задания + материалы.
- Ручной ввод оценок; импорт всех курсов с разделением текущие/прошлые; автосоздание предметов расписания из курсов LMS.
- Казахский перевод делается без блокировки на носителя; спорные строки — в список на проверку.
