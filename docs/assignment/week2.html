1. Процесс после внедрения (TO-BE)

1. Участник группыменяет пару (кабинет, время, отмена) в приложении
→
2. Приложениесразу сохраняет в базу на телефоне
→
3. Синхронизацияотправляет изменение на сервер, когда есть сеть
→
4. Серверраздаёт изменение всей группе
→
5. Участниксоздаёт задание, ставит «Для группы», прикрепляет файл
→
6. Студентывидят задание у себя в списке
→
7. Студентв цоколе без сети открывает пару и задачу
→
8. Студентотмечает задачу сделанной, отметка уйдёт при появлении сети
Рис. 1. TO-BE: двойная рамка — автоматизированные шаги

Что автоматизируется: рассылка изменений (шаги 3–4 вместо скриншота в чат), доставка задания группе (шаг 6), доступ без сети (шаг 7), подсчёт недели числитель/знаменатель и отправка отметок после восстановления связи (шаг 8).

Важно: в приложении нет отдельной роли «староста». Все участники группы равны, задание для группы может опубликовать любой. Обычно это делает староста, но ему не нужны особые права.

Ограничения и допущения

  • Ограничение 1: файл материала — не больше 10 МБ.
  • Ограничение 2: доступа к серверам и базе вуза нет, все данные вводят сами студенты.
  • Ограничение 3: веб-версия работает только при открытой вкладке и не получает уведомления.
  • Допущение 1: часы на телефоне и сервере идут примерно одинаково (нужно для LWW).
  • Допущение 2: в группе не больше 40 человек.

Контрольный вопрос

Как проверить, что требование выполнено? У каждого требования есть критерий приёмки. Его проверяем по сценарию «условие → действие → результат» (раздел 7). Если результат совпал — требование выполнено. Требования к безопасности и синхронизации дополнительно проверяют автотесты сервера, скорость — секундомером.
