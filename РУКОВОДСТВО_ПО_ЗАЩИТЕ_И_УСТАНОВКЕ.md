## 2. Быстрый запуск проекта перед защитой

### Шаг 1. Запуск сервера API и приложения
Дважды кликните по файлу **`ЗАПУСК_СЕРВЕРА.bat`** в корне проекта (или выполните в терминале `cd backend && npm start`).
Сервер запустится, автоматически определит ваш текущий IP-адрес Wi-Fi и выведет:
* Локальный адрес на ПК: `http://localhost:3000`
* Сетевой адрес для смартфона (например, `http://10.200.4.21:3000`)
* **QR-код прямо в окне консоли** для быстрого открытия камерой телефона.

### Шаг 2. Запуск приложения на реальном смартфоне
1. Подключите ваш смартфон (Android или iPhone) к той же Wi-Fi сети, что и компьютер.
2. Откройте камеру смартфона и **отсканируйте QR-код из консоли**, либо откройте в мобильном браузере сетевой адрес (например: `http://10.200.4.21:3000`).
3. *(По желанию)* В меню браузера нажмите **«Добавить на главный экран»** — приложение развернётся на весь экран без рамок браузера, как нативное мобильное приложение.
4. *(Если смартфон на мобильном интернете 4G без общего Wi-Fi)* Запустите файл **`ИНТЕРНЕТ_ДОСТУП_ДЛЯ_ТЕЛЕФОНА.bat`** для создания защищенного интернет-туннеля.

### Шаг 3. Запуск приложения на компьютере (Windows Desktop)
Дважды кликните по файлу **`ЗАПУСК_ПРИЛОЖЕНИЯ_WINDOWS.bat`** — запустится скомпилированный Release-бинарник `studyplan.exe`.

## 4. Сценарий защиты на 5 минут (Пошаговый план речи)

### 1. Введение и актуальность (30 секунд)
> «Здравствуйте, уважаемые члены комиссии! Тема моего курсового проекта — кроссплатформенное мобильное приложение **StudyPlan** для управления учебным расписанием и дедлайнами студентов.  
> Главная особенность проекта — архитектура **Offline-First**: студенты часто учатся в цокольных этажах и аудиториях без интернета, поэтому приложение сохраняет 100% данных в локальной базе данных на устройстве и фоново синхронизирует их с сервером при появлении сети.»

### 2. Запуск и демонстрация на смартфоне (1 минута)
> «Приложение запущено на реальном смартфоне.  
> 1. При старте отображается анимированный **Splash Screen** с микроанимацией логотипа и проверкой сессии в памяти устройства.  
> 2. На экране авторизации реализована строгая валидация (формат email, длина пароля).  
> 3. В правом верхнем углу находится кнопка настройки сетевого API сервера с функцией проверки связи (Ping `/api/health` — 200 OK).»

### 3. Главный экран: Таймлайн дня и Расписание (1 минута)
> «После входа открывается главный экран — **Таймлайн текущего дня**:  
> * Видна почасовая сетка занятий, статус текущей пары ("Идёт сейчас"), аудитория, преподаватель и тип пары.  
> * При нажатии на карточку пары можно сразу создать дедлайн по этому предмету.  
> * В разделе **Полное расписание** поддержан переключатель четных и нечетных недель (числитель/знаменатель) и фильтр по дням недели.»

### 4. Трекер дедлайнов и полный CRUD (1 минута)
> «В разделе **Дедлайны и задачи** продемонстрирован полный цикл CRUD:  
> * **Create (Создание):** есть быстрый ввод через Inbox и расширенная форма с выбором предмета, приоритета, даты сдачи, чек-листа подзадач и прикреплением файлов.  
> * **Read (Чтение):** фильтрация по статусу ("Все", "В работе", "Выполненные") и поиск задач по тексту на лету.  
> * **Update (Редактирование):** отметка выполнения в один клик с обновлением прогресса.  
> * **Delete (Удаление):** быстрое удаление свайпом (Dismissible) с мягким удалением в базе данных.»

### 5. Архитектура и взаимодействие компонентов (1 минута)
> «Архитектура проекта состоит из двух ключевых уровней:  
> 1. **Клиентская часть:** Flutter (Dart 3) с реактивным локальным хранилищем на **Drift (SQLite)** и архитектурным паттерном **BLoC**.  
> 2. **Серверная часть:** Node.js, Express, Knex Query Builder и SQLite/PostgreSQL. Доступ к данным строго изолирован через защищенный REST API с токенами JWT и алгоритмом синхронизации Last-Write-Wins.

> Приложение готово к практическому использованию. Спасибо за внимание, готов ответить на вопросы!»
